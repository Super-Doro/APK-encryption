# Doro加密

安卓原生 Java 项目，完全离线处理 APK 和 SH。安装 `Doro加密-3.0.6.apk` 后，选择文件，点击“开始加密”，分别导出加密文件和密钥文件。3.0 版采用浅色简约界面，底部切换“加密”和“记录”。成功生成后自动清空文件选择并重置策略，文件和密钥保留在记录页。

## APK 使用方式

每次处理都会产生新的包标识和 AES-256 密钥，包括重复处理同一个原 APK。原 DEX 代码使用 AES-GCM 加密，输出包包含启动壳、加密代码、公钥及原有资源。专属密钥使用发行端 RSA-PSS 签名，同时绑定包标识、原包名和 AES 密钥。

安装输出 APK，第一次打开时输入对应的 `FA2.` 密钥。验证和解密成功后自动启动原应用。激活记录由该应用自己的 Android Keystore 加密保存，后续打开会自动解锁。更新为新一轮加密输出后需要新密钥。

本版面向 Android 10 及以上的普通独立 APK。拆分包和要求 sharedUserId 的应用会被拒绝。按 APK 结构、服务类型依赖和用户选择生成隔离进程策略。3.0 版移除了 APK、SH 和总代码的固定大小限制，采用带完整性校验的分块加密，并显示处理阶段和进度。实际处理能力取决于设备可用存储、内存和 Android 运行时。隔离服务分析和代码改写仍需在内存中解析 DEX，单个 DEX 受 Java 缓冲区寻址范围约束。

处理会重新签名，并保留原包名。与原软件签名不同的情况下，安装前通常需要卸载原软件，卸载会清除它的数据。原软件的签名校验、登录 SDK、支付 SDK、其他加固壳或自定义加载机制可能需要专项适配。当前已验证项目中的原生样例，实际第三方 APK 需要逐个实测。

代码加密覆盖 DEX。资源、assets 和原生 `.so` 保留原格式以供系统和原应用使用。离线加密无法承诺抵抗所有运行时提取或修改。

### 隔离进程策略

隔离服务的 `isolatedProcess` 属性保持启用。主进程解锁后，通过显式绑定向隔离进程交付一个临时 Binder 授权通道。隔离进程验证该输出包的签名密钥，在内存中解密代码，并在绑定阶段恢复原服务。授权通道限制到当前 Android 用户的隔离 UID。用户需要先打开受保护应用完成解锁，供外部调用的隔离服务随后由宿主进程预热。内部服务在实际绑定时取得授权，以保留它们的启动时机。

加密界面提供三种初始化策略。

| 策略 | 处理方式 |
| --- | --- |
| 自动分析 | 检查隔离服务、其内部 Binder 类、父类和可识别的上下文类型引用。显式依赖自定义 Application 时保留原初始化，其余服务采用基础初始化。 |
| 保留原初始化 | 使用原组件工厂创建 Application，并执行其初始化流程，适用于依赖应用状态或依赖注入的服务。 |
| 基础初始化 | 为隔离进程创建基础 Application，适用于不依赖主进程初始化的独立服务。 |

每个隔离服务都有独立的处理计划。声明共享隔离进程的服务会使用一致的 Application 策略。在记录页点击“更多”中的“查看处理策略”，可查看每个服务的选择与原因。旧记录保留原有文件和密钥，新生成的文件采用本次选择的策略。

自动分析覆盖可识别的静态类型引用。反射、跨多层帮助类的间接依赖、动态 DEX、Native 加载及自定义框架仍需运行验证。模式在生成阶段确定，运行失败会报告具体初始化原因，可以切换策略重新生成。Android 非 SDK 接口的差异由加密壳的运行时桥接层处理，系统升级可能需要更新桥接层。

加密壳自带 HiddenApiBypass 6.1，其类名被迁移到独立命名空间，以避免与原应用依赖冲突。授权后的隔离服务通过这套桥接层恢复 Application 和 Service 上下文。运行时、授权策略和生成代码均按 APK 的组件元数据工作。支持常用 `bindService`、`bindIsolatedService`、Executor 和 Android 14+ `BindServiceFlags` 形式，并保留原 DEX 版本。


## SH 使用方式

选择 `.sh`，输出仍为 `.sh`，每次生成独立密钥。3.0.1 版按原始字节流处理脚本，保留原有编码和内容。脚本使用 AES-GCM 加密，自带安卓 Java 解密运行时，使用系统 `app_process`、`base64`、`sed` 和 `mktemp`，无需服务器。

在安卓 Shell 中运行以下命令，按提示输入专属密钥。

```sh
sh 加密脚本.sh
```

需要传递原脚本参数时，将密钥作为第一个参数。

```sh
sh 加密脚本.sh 'FA2.完整密钥' 参数1 参数2
```

脚本采用流式读取和分块加密，移除了原有 16MB 限制。执行采用 Android 自带 `/system/bin/sh`，脚本使用的编码、外部命令和权限仍须由执行环境支持。解密运行不会自动获得 root 权限。此前版本已在 Android 16 的 ADB Shell 验证参数、输出和退出码。

3.0.3 版采用 Android 批量 Base64 编码和 256KB 文件写入缓冲，减少大脚本输出时的小块写入。缓冲写完并同步到存储后才提交生成记录。实际加密耗时尚未进行设备测量。

3.0.4 版在首页显示版本号，细化 SH 的处理阶段。生成失败时显示当前阶段、异常类型和完整调用堆栈，可点击“复制错误详情”反馈。用户报告的再次出现 `Input length = 1` 的原因仍待完整异常确认。

3.0.5 版更名为 Doro加密，并使用蓝色 D 图标。首页右上角“日志”可以查看和复制本机保存的错误日志，包括版本、发生时间、设备信息、当前文件、处理阶段和异常堆栈。处理失败与可捕获的未处理异常会保存日志，重启软件后可查看。日志保存在应用私有目录，清除应用数据或卸载会清除日志。

运行时会在 `${TMPDIR:-/data/local/tmp}` 创建私有临时目录，解密脚本以仅所有者可读写的临时文件执行，正常结束后清理。强制终止或设备断电可能中断清理。3.0.2 版直接使用 `/system/bin/sh` 执行解密后的临时脚本，`$0` 指向该临时脚本，读取自身内容的操作可取得恢复后的原始字节。原脚本参数、调用时工作目录和退出码保留。依赖固定文件名、原脚本所在目录资源或指定安装路径的脚本仍需结合具体脚本适配。

## 密钥与记录

密钥绑定每次生成的输出文件，同名文件重新加密也会得到不同密钥。新密钥仅适用于本轮输出，旧文件继续使用其原有密钥。APK 和 SH 之间、不同生成轮次之间均校验独立生成编号与文件身份。记录显示应用标识、文件名、生成编号及对应密钥，支持复制完整密钥，并按应用标识、文件名或生成编号搜索。密钥不绑定手机，同一份输出文件和对应密钥可以在多台设备使用。

软件内部保留生成记录和配套密钥，清除数据或卸载软件会丢失这些记录。请导出并保管需要的文件和密钥。已导出的文件及其密钥在卸载生成器后仍可使用。发行端签名私钥和 APK 重签名私钥都保存在本机 Android Keystore，不可导出，重装生成器后会产生新的签名身份。

当前生成器 APK 使用开发签名。生成的受保护 APK 使用生成器手机自身的独立签名身份，支持 V1、V2、V3 签名，生成后会自动验证签名。

## 构建

需要 JDK 17、Android SDK Platform 35 和 Build Tools 35.0.0。设置 `JAVA_HOME` 和 `ANDROID_HOME`，在 PowerShell 中执行。

```powershell
./gradlew.bat :app:assembleDebug
```

生成器位于 `app/build/outputs/apk/debug/app-debug.apk`。构建会自动生成 APK 启动壳和 SH 运行时，并作为资源打入生成器。手机端加密、签名和导出均在本地完成。

`app` 包含生成器、策略分析、二进制 Manifest 修改和 APK 重签名。`shell` 包含解锁界面、组件工厂、隔离桥接层和内存 DEX 加载。`script` 包含 SH 解密执行入口。`shared` 包含 AES-GCM 及 RSA-PSS 密钥协议。`fixture`、`scenarios` 与 `androidTest` 用于测试。

## 验证范围

3.0.6 版使用项目根目录的 `image.jpg` 作为应用图标。

3.0 至 3.0.6 版按要求仅完成构建打包，未执行新版运行测试与界面验证。以下为此前版本的验证记录。

已在 Android 16 模拟器验证独立样例 APK 的加密、签名、安装、错误密钥拒绝、正确密钥自动启动、重启后恢复激活，以及原 Application、Provider、AppComponentFactory 和资源读取。另验证了重复加密产生不同密钥、两份 APK 的密钥交叉拒绝、SH 执行与退出码、APK 密钥无法解锁 SH。静态检查覆盖生成器、APK 启动壳和 SH 运行时。

生成器界面的文件导入、加密按钮、APK/SH 导出和密钥保存已通过设备测试，并使用独立 Node.js 实现核对导出的文件、密钥、RSA-PSS 签名和 AES-GCM 解密结果。

2.2 版在 Android 16 模拟器中覆盖默认 Application、主进程读取偏好设置、同一 APK 内不同服务分别采用不同初始化方式，以及手动指定策略。测试源 APK 均不包含兼容库。验证范围包括自定义组件工厂、隔离 Binder 调用、命名隔离服务实例、新版绑定参数和冷启动恢复。

冰箱 3.30.14 G 作为第三方回归样例，测试解锁、界面启动、隔离服务和外部 Binder 连接。ADB、Shizuku、设备管理员模式下的实际冻结动作尚未在具备相应授权的真机上验证。
